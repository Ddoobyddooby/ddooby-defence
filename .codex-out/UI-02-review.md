## F1 — 낮음: 배속 단축키가 요청의 `=`와 다르고 수정키 조합에서도 발동

- 위치: `src/game/ui/GameApp.tsx:56-59`. `KeyF`를 받아 배속을 순환하며 `ctrlKey`/`metaKey`/`altKey`를 확인하지 않는다. `docs/UI-CONTRACT.md:51`의 배속 규칙에는 단축키가 없다.
- 재현: 640×320 브라우저에서 세션 배속 1× 상태로 `=` 입력 → 1× 유지. `f` 입력 → 2×. `Ctrl+F`에 해당하는 `keydown`(`code=KeyF`, `ctrlKey=true`) 입력 → 5×. 브라우저 찾기 같은 수정키 조합이 게임 배속도 바꿀 수 있다.
- 영향: 요청에서 점검 대상으로 지정한 `=` 키가 작동하지 않고, 사용자가 웹 브라우저의 찾기를 열 때 의도치 않게 게임 속도가 바뀔 수 있다. Space/P/Esc 자체와의 충돌은 확인되지 않았다.
- 수정 제안: 의도한 단축키가 `=`인지 확정한 뒤 `Equal`로 구현하거나 `F`를 계약에 명시한다. 단축키를 유지할 경우 수정키 입력과 편집 가능한 요소에서의 입력을 제외한다. 단축키 회귀 테스트를 추가한다.

## 확인한 동작과 검증 한계

- 코드상 게임 누적은 `elapsedMs × speed`, 호출당 최대 틱은 `5 × speed`; `frameDelta`가 먼저 250ms로 제한하므로 5×에서도 한 프레임 최대 25틱이다. 결과 도달 시 while 조건에서 더 진행하지 않고 누적을 0으로 지운다. `stepOnce`의 명령 적용·pending 해제와 코어 틱 길이는 변경되지 않았다.
- 숨김은 `setHidden`에서 누적을 지우고 자동 일시정지하며, 복귀 첫 `advance`는 버린다. 일시정지·결과에서는 틱이 진행하지 않는다. 배속은 같은 세션의 재도전·스테이지 선택 복귀 때 유지되고 새 `GameSession`은 1×이다. UI 피드백 시계는 배속을 곱하지 않는다. `hudView`는 전달된 배속을 상태에 넣는 순수 파생 함수다.
- `prepRemainingText`는 0/1/20/21틱에서 각각 0/1/1/2초로 올림 처리한다. 남은 시간이 있는 1틱에서 0초가 먼저 표시되지 않는다.
- 직접 실행: `npm test -- src/game/session/session.test.ts src/game/session/hudView.test.ts` **2파일/103테스트 통과**. 640×320 브라우저 정적 빌드에서 준비 HUD와 선택 타워 패널을 확인했다. 선택 상태 `hud.clientHeight=320`, `scrollHeight=320`, 선택 패널 하단 312px로 하단 8px 여백 및 스크롤 없음 확인. 선택 패널은 브라우저 런타임에서 세션 API로 타워를 설치·선택해 측정했다. 해당 정적 빌드에 최신 `clamp(12px,5vh,24px)` 스타일이 포함된 것을 확인했다.
