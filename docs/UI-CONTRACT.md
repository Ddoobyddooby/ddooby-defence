# Ddooby-defence — UI 계약 (UI-01, v0.1)

> 상태: **claude-main 설계 v0.1, 2026-11-25.** 사용자 결정(2026-11-25): 그래픽은 **단순 도형 자리표시**(실제 스프라이트는 후속 디자인 태스크에서 교체), 화면 글자는 **한국어**, 지원 화면은 **모바일 가로 화면까지**(터치 포함).
> 기준: SPEC 9·10절(UI·진행), PLAN 2·6절(계층·입력 경계), SIM-CONTRACT 2절(벽시계 연결)·10.1절(입력 좌표 → 칸)·12~15절(시도 코어). 우선순위 SPEC > SIM-CONTRACT > 이 문서 > PLAN.
> 게임 규칙은 **코어가 유일한 진실 원천**이다. UI·Phaser는 코어 스냅샷·이벤트를 읽고 코어 명령만 보낸다. UI가 규칙을 흉내 내 결과를 바꾸면 안 된다.

## 1. 계층과 파일

| 계층 | 위치 | 책임 | 금지 |
|---|---|---|---|
| 코어 | `src/game/core/**` | 틱·전투·경제·결과(기존) | UI·프레임워크 import(기존 lint) |
| 세션 | `src/game/session/**` (신규, 순수 TS) | 시도 생성·재도전, 벽시계 → `step()` 연결, 명령 제출, UI 상태(선택·판매 확인), HUD 뷰 모델 파생, 스테이지 진행 상태(세션 메모리) | React·Phaser·DOM import, 게임 규칙 재구현 |
| 렌더 | `src/game/phaser/**` | 맵·타워·적·투사체·VFX 그리기, 포인터 → 칸 변환 후 세션에 전달 | 게임 상태 보관·수정 |
| HUD·화면 | `src/app/**`, `src/game/ui/**`(신규, React) | 스테이지 선택·HUD·오버레이·결과 화면 | 코어 직접 호출(세션 경유) |
| 임시 콘텐츠 | `src/game/content/devBundle.ts` (신규) | 화면에서 실제로 플레이할 **개발용 임시 수치** 묶음 | 밸런스 승인값처럼 표기 |

- 세션 폴더도 코어와 같은 framework-free lint 경계를 적용한다(`eslint.config.mjs`에 경로 추가). 세션은 결정성 금지 규칙(`Math.random`·`Date` 등)의 적용 대상이 아니지만, **시간은 외부에서 주입**받아 테스트 가능해야 한다(`advance(elapsedMs)`).

## 2. 임시 콘텐츠 (DEV_PLACEHOLDER)

- 실제 수치(TBD-TOWER/ENEMY/ECON/WAVE)는 BAL-01 전까지 미승인이다. 화면에서 플레이하려면 검증기를 통과하는 묶음이 필요하므로 `devBundle.ts`에 **`DEV_PLACEHOLDER`** 표식을 단 임시 묶음을 둔다.
- 파일 머리 주석·export 이름·화면에 모두 "임시 수치"임을 드러낸다: HUD 상단에 작은 배지 `임시 수치`.
- 맵은 승인된 후보 맵(`STAGE_MAPS`)을 그대로 쓴다. 웨이브는 3스테이지 × 5웨이브, Stage 1 등장 조건(SIM-CONTRACT 11.3)·사거리 순서 등 검증기 규칙을 모두 만족해야 한다(테스트로 `validateContent` 통과 단언).
- 이 값은 "플레이가 되는지" 확인용이며 난이도 조정 대상이 아니다. BAL-01이 이 파일을 승인 수치로 교체한다.

## 3. 화면 크기·배치 (사용자 결정: 모바일 가로까지)

- **지원 최소 뷰포트:** 가로 **800 × 360** CSS px(모바일 가로). 이보다 작거나 **세로 방향**(높이 > 너비)이면 게임 대신 "가로 화면으로 돌려 주세요 / 창을 넓혀 주세요" 안내를 표시한다. 기준 데스크톱은 1280 × 720 이상.
- **배치:** 왼쪽 맵, 오른쪽 HUD(SPEC 9절). HUD 폭 `hudW = clamp(round(뷰포트 너비 × 0.24), 176, 320)` px. 맵 타일 `tile = floor(min((너비 − hudW) / 18, 높이 / 10))` px(정수, 최소 18). 맵 영역 `18·tile × 10·tile`은 남는 공간 가운데에 배치하고 나머지는 레터박스.
- **HUD 높이 부족 시:** HUD는 세로 스크롤 가능하되 **골드·기지 HP·웨이브·단계·일시정지 버튼**은 상단 고정(항상 보임, SPEC 9절).
- **터치:** 모든 조작은 탭(클릭과 동일)으로 가능해야 한다. 호버 전용 정보 금지. 버튼·타워 선택 항목의 터치 영역은 최소 40 × 40 CSS px. 더블탭 확대·스크롤로 맵이 움직이지 않게 맵 영역에 `touch-action: none`.
- 창 크기 변경·회전 시 다시 배치하며 게임 상태(세션·시도)는 그대로 유지한다. 지원 크기 미달·세로 안내 화면으로 바뀌면 Phaser 렌더 인스턴스는 다시 만들어도 되지만, 진행 중 시도(준비·전투 단계)는 **일시정지**로 전환해 안내 중 시간이 몰래 멈추거나 흐르지 않게 한다(리뷰 UI-01 F2).

## 4. 화면 흐름

```text
스테이지 선택 ──(선택 가능 카드)──▶ 전투 화면 ──(결과)──▶ 결과 오버레이
     ▲                                  │  ▲                │ 재도전 → 새 시도(같은 스테이지)
     └──────── 스테이지 선택 ◀───────────┘  └─ 일시정지 오버레이 │ 다음 스테이지(유효할 때) / 스테이지 선택
```

- **스테이지 카드 상태:** `잠김` · `선택 가능` · `클리어` · `콘텐츠 오류`(검증 실패, 진단 문구 표시, 선택 불가). 해금: Stage 1은 항상 선택 가능, Stage N은 Stage N−1 클리어 시(SPEC 10절 "플래그에서 파생"). UI-01에서 클리어 플래그는 **세션 메모리**에만 있다. 영구 저장·저장 상태(대기·성공·실패)는 SAVE-01이 같은 인터페이스(`ProgressStore`)로 연결한다.
- **진입:** `validateStageForEntry`(진입 재검증) 실패 시 시작하지 않고 카드를 `콘텐츠 오류`로 표시.
- **재도전:** 같은 스테이지로 새 `attemptId` 시도(`createAttempt`), 이전 시도 상태를 넘기지 않음. 클리어 플래그 유지.
- **결과 오버레이:** Stage 이름·도달 웨이브·남은 기지 HP, 버튼 `재도전`·`스테이지 선택`·`다음 스테이지`(Stage 3에는 없음, 다음 스테이지가 콘텐츠 오류면 비활성). 결과 단계에서는 게임플레이 입력이 코어에서 거부되며 UI도 조작을 막는다.

## 5. 세션: 시간·명령

- `advance(elapsedMs)`: 누적 후 50ms마다 `step()` 1회, **한 번에 최대 5틱**, 나머지 누적은 버린다(SIM-CONTRACT 2절). 일시정지·결과 단계·화면 숨김(`visibilitychange` hidden)에서는 누적하지 않는다. 숨김 → 보임 복귀 시 자동 일시정지하지는 않지만 누적은 0부터 시작.
- 일시정지: 버튼(HUD 상단)과 키보드 `Space`/`P`. 코어 `pause()`/`resume()`을 쓰고, 렌더 VFX도 함께 멈춘다(SPEC 9절). 일시정지 중 게임플레이 조작 버튼은 비활성.
- 명령은 모두 세션 메서드로: `build(type, cell)`, `upgrade(towerId)`, `sell(towerId)`, `setTargeting(towerId, mode)`, `startWave()`. 세션은 접수 결과와 **다음 틱 이벤트의 `commandRejected`**를 받아 사용자 피드백으로 바꾼다. UI가 미리 막는 조건(골드 부족 버튼 비활성 등)은 **표시 편의**일 뿐이며, 최종 판정은 항상 코어다.
- 기록: 세션은 `createRecordedAttempt`로 시도를 만든다(나중에 리플레이·버그 재현용으로 `finish()` 가능). 이 기록은 UI-01에서 저장하지 않는다.

## 6. 맵 입력·선택 상태 (UI 상태, 코어 밖)

| UI 상태 | 진입 | 맵 탭 동작 | 해제 |
|---|---|---|---|
| 기본 | — | 타워 있는 칸 → 그 타워 선택. 빈 칸 → 선택 해제 | — |
| 설치 모드(종류 T) | HUD 타워 목록에서 T 탭 | 칸 → `build(T, 칸)` 제출 후 **설치 모드 종료**(성공·실패 무관, SPEC 9절 "1개 설치하고 종료") | 같은 항목 다시 탭, `Esc`, 맵 밖 탭 |
| 타워 선택(id) | 맵의 타워 탭 | 기본과 같음 | 빈 칸 탭, `Esc`, 타워 판매·사라짐 |
| 판매 확인(id) | 상세의 `판매` | 확인창 표시 중 맵 입력 무시 | `취소`, **준비→전투 전환 시 자동 취소**(SPEC 9절), 타워 사라짐 |

- 좌표 변환: Phaser 포인터 좌표(맵 영역 기준) → `pointToCell(x, y, tile)`(SIM-CONTRACT 10.1). `null`(맵 밖·레터박스)이면 설치 명령을 만들지 않는다. HUD는 DOM이므로 HUD 탭이 맵 명령을 만들 수 없다.
- 설치 모드에서 칸 위 미리보기: 설치 가능/불가 색, 그 종류 Lv1 사거리 원. 터치 기기는 미리보기 없이 탭 즉시 제출(호버 없음).
- 선택된 타워: 사거리 원 표시, HUD에 상세(종류·레벨·현재 능력치·타깃 모드·강화 가격·환급 예상액).
- 일시정지 해제 후 남은 UI 상태(선택·설치 모드)는 유지하되 명령은 코어가 재검증(SPEC 9절).

## 7. HUD 내용 (SPEC 9절)

- **상단 고정:** 스테이지 이름, 웨이브 `N / 5`, 단계(`준비`·`전투`·`승리`·`패배`, 일시정지 시 `일시정지` 표시), 골드, 기지 HP(`현재 / 최대`), 일시정지 버튼, `임시 수치` 배지.
- **준비:** 남은 시간(초, 소수 1자리 = 틱 × 0.05), `지금 시작`(조기 시작, 준비 단계에서만 활성).
- **전투:** 생성 진행 `생성 k / 전체`, 생존 적 수.
- **타워 목록 4종:** 이름·설치 가격, 골드 부족이면 흐리게(탭은 가능하되 코어 거부 피드백).
- **타워 상세:** 6절. `강화`(Lv4면 `최고 레벨`, 비활성), `판매`(준비 단계에서만 활성, 전투 중엔 "준비 단계에서만 판매" 안내), 타깃 모드 4버튼 `선두`·`후미`·`가까운`·`강한`.
- **피드백:** 거부 사유를 짧은 한국어 문구로 2초 표시. 사유 문구 표(`insufficientGold` → "골드가 부족합니다", `notBuildable` → "여기에는 설치할 수 없습니다", `occupied` → "이미 타워가 있습니다", `outOfGrid` → "맵 밖입니다", `maxLevel` → "최고 레벨입니다", `wrongPhase` → "지금은 할 수 없습니다", `towerNotFound` → "타워가 없습니다"). 그 밖의 사유는 "명령이 거부되었습니다(사유 코드)".
- 화면 문구는 한 파일(`src/game/ui/strings.ko.ts`)에 모은다.
- 표시 값은 모두 **코어 스냅샷에서 파생**하는 순수 함수(`hudView(snapshot, stage, uiState)`)로 만든다. HUD가 따로 값을 계산·누적하지 않는다.

## 8. 렌더 (단순 도형, 사용자 결정)

- 스테이지별 팔레트(DESIGN.md 시안 색감): Stage 1 잔디 초록·황토 길, Stage 2 눈 흰색·회청 길, Stage 3 어두운 석재·밝은 석판 길. 격자선 낮은 대비. 출발 칸·기지(성문) 칸 표식.
- 타워: 칸 안 정사각형 + 종류 색(궁수 금색·발리스타 적색·마법 보라·서리 하늘색) + 레벨 표시(점 1~4). 적: 원 + 유형 색, 크기 차이(군집형 작게·중장형 크게), HP 바, 특성 표식(작은 모서리 기호 3종). 투사체: 작은 점(마법은 원형 폭발 짧은 링, 서리 명중은 청백 링).
- 위치는 코어 상태(`progressToPosition`, 투사체 `pos`)를 그대로 그린다. **틱 사이 보간**은 허용하되 시각 전용이며(직전·현재 스냅샷 선형 보간) 게임 상태에 영향 없음. 취소·만료 투사체의 잔상·폭발 링 같은 VFX는 이벤트로 그리고 짧은 시간 뒤 사라진다. 일시정지 시 VFX도 정지.
- 실제 스프라이트 교체를 위해 그리기를 종류별 함수로 분리(`drawTower(type, level)` 등).

## 9. 검증 (완료 조건, TASKS UI-01)

- **단위(vitest, 순수 TS):** 세션 `advance`(50ms 누적·최대 5틱·일시정지/숨김/결과에서 0틱), 명령 전달과 거부 피드백 매핑, UI 상태 전이(설치 모드 1회 종료·판매 확인 자동 취소·타워 사라짐 시 해제), `hudView` 값이 스냅샷과 일치, 레이아웃 계산(800×360·1280×720·1920×1080·세로 방향 안내), 맵 좌표 → 칸(레터박스·HUD 영역 → null), 진행 상태(해금 파생·콘텐츠 오류 카드), `devBundle` 검증 통과.
- **브라우저(ego-browser, 사용자 지침):** `npm run dev`로 실제 화면에서 — 스테이지 선택 → Stage 1 진입, 설치(성공·골드 부족·경로 칸 거부), 강화·타깃 변경·판매 확인/취소, 조기 시작, 일시정지/재개, 승리 또는 패배 결과 → 재도전·스테이지 선택. 1280×720과 800×360(가로) 두 크기에서 스크린샷. HUD 값과 실제 상태 일치 확인. 결과는 스크린샷 경로와 함께 보고.
- 기존 `npm run lint`/`typecheck`/`test`/`build` 통과. 코어(`src/game/core/**`)는 수정하지 않는 것이 원칙이며, 필요하면 먼저 claude-main에 질문.
