# Ddooby-defence — UI 계약 (UI-01, v0.1)

> 상태: **claude-main 설계 v0.1, 2026-11-25.** 사용자 결정(2026-11-25): 그래픽은 **단순 도형 자리표시**(실제 스프라이트는 후속 디자인 태스크에서 교체), 화면 글자는 **한국어**, 지원 화면은 **모바일 가로 화면까지**(터치 포함).
> 기준: SPEC 9·10절(UI·진행), PLAN 2·6절(계층·입력 경계), SIM-CONTRACT 2절(벽시계 연결)·10.1절(입력 좌표 → 칸)·12~15절(시도 코어). 우선순위 SPEC > SIM-CONTRACT > 이 문서 > PLAN.
> 게임 규칙은 **코어가 유일한 진실 원천**이다. UI·Phaser는 코어 스냅샷·이벤트를 읽고 코어 명령만 보낸다. UI가 규칙을 흉내 내 결과를 바꾸면 안 된다.

## 1. 계층과 파일

| 계층 | 위치 | 책임 | 금지 |
|---|---|---|---|
| 코어 | `src/game/core/**` | 틱·전투·경제·결과(기존) | UI·프레임워크 import(기존 lint) |
| 세션 | `src/game/session/**` (신규, 순수 TS) | 시도 생성·재도전, 벽시계 → `step()` 연결, 명령 제출, UI 상태(선택·판매 확인), HUD 뷰 모델 파생, 스테이지 진행 상태(세션 메모리) | React·Phaser·DOM import, 게임 규칙 재구현 |
| 렌더 | `src/game/phaser/**` | 맵·타워·적·투사체·VFX 그리기, 포인터 → 칸 변환 후 세션에 전달 | 게임 상태 보관·수정 |
| HUD·화면 | `src/app/**`, `src/game/ui/**`(신규, React) | 스테이지 선택·HUD·오버레이·결과 화면 | 코어 직접 호출(세션 경유) |
| 임시 콘텐츠 | `src/game/content/devBundle.ts` (신규) | 화면에서 실제로 플레이할 **개발용 임시 수치** 묶음 | 밸런스 승인값처럼 표기 |

- 세션 폴더도 코어와 같은 framework-free lint 경계를 적용한다(`eslint.config.mjs`에 경로 추가). 세션은 결정성 금지 규칙(`Math.random`·`Date` 등)의 적용 대상이 아니지만, **시간은 외부에서 주입**받아 테스트 가능해야 한다(`advance(elapsedMs)`).

## 2. 임시 콘텐츠 (DEV_PLACEHOLDER)

- 실제 수치(TBD-TOWER/ENEMY/ECON/WAVE)는 BAL-01 전까지 미승인이다. 화면에서 플레이하려면 검증기를 통과하는 묶음이 필요하므로 `devBundle.ts`에 **`DEV_PLACEHOLDER`** 표식을 단 임시 묶음을 둔다.
- 파일 머리 주석·export 이름·화면에 모두 "임시 수치"임을 드러낸다: HUD 상단에 작은 배지 `임시 수치`.
- 맵은 승인된 후보 맵(`STAGE_MAPS`)을 그대로 쓴다. 웨이브는 3스테이지 × 5웨이브, Stage 1 등장 조건(SIM-CONTRACT 11.3)·사거리 순서 등 검증기 규칙을 모두 만족해야 한다(테스트로 `validateContent` 통과 단언).
- 이 값은 "플레이가 되는지" 확인용이며 난이도 조정 대상이 아니다. BAL-01이 이 파일을 승인 수치로 교체한다.

## 3. 화면 크기·배치 (사용자 결정: 모바일 가로까지)

- **지원 최소 뷰포트:** 가로 **640 × 320** CSS px(모바일 가로). 처음 800×360으로 정했으나 실기기(Galaxy A16, 카메라 구멍 제외 약 796×384 CSS px)에서 안내 화면이 떠서 MOB-01에서 낮췄다(iPhone SE 667×375도 포함). 이보다 작거나 **세로 방향**(높이 > 너비)이면 게임 대신 "가로 화면으로 돌려 주세요 / 창을 넓혀 주세요" 안내를 표시한다. 기준 데스크톱은 1280 × 720 이상.
- **배치:** 왼쪽 맵, 오른쪽 HUD(SPEC 9절). HUD 폭 `hudW = clamp(round(뷰포트 너비 × 0.17), 136, 240)` px(MOB-02 사용자 결정 2026-11-26: HUD를 줄여 18×10 격자는 유지하고 칸을 키움. 이전 `× 0.24, 176, 320`). 맵 타일 `tile = floor(min((너비 − hudW) / 18, 높이 / 10))` px(정수, 최소 18). 맵 영역 `18·tile × 10·tile`은 남는 공간 가운데에 배치하고 나머지는 레터박스.
- **HUD 한 화면:** 640×320 이상 모든 지원 크기에서 HUD는 **스크롤 없이** 7절의 상시 항목이 모두 보여야 한다(MOB-01 리뷰 F1). 넘칠 위험이 있는 정보는 메뉴·타워 정보 창(7절)으로 보낸다.
- **예시(계산값):** 640×320 → hudW 136, tile 28, 맵 504×280 · 796×384(테스트 폰) → hudW 136, tile 36, 맵 648×360 · 1280×720 → hudW 218, tile 59 · 1920×1080 → hudW 240, tile 93.
- **터치:** 모든 조작은 탭(클릭과 동일)으로 가능해야 한다. 호버 전용 정보 금지. 버튼·타워 선택 항목의 터치 영역은 최소 40 × 40 CSS px. 더블탭 확대·스크롤로 맵이 움직이지 않게 맵 영역에 `touch-action: none`.
- 창 크기 변경·회전 시 다시 배치하며 게임 상태(세션·시도)는 그대로 유지한다. 지원 크기 미달·세로 안내 화면으로 바뀌면 Phaser 렌더 인스턴스는 다시 만들어도 되지만, 진행 중 시도(준비·전투 단계)는 **일시정지**로 전환해 안내 중 시간이 몰래 멈추거나 흐르지 않게 한다(리뷰 UI-01 F2).

## 4. 화면 흐름

```text
스테이지 선택 ──(선택 가능 카드)──▶ 전투 화면 ──(결과)──▶ 결과 오버레이
     ▲                                  │  ▲                │ 재도전 → 새 시도(같은 스테이지)
     └──────── 스테이지 선택 ◀───────────┘  └─ 일시정지 오버레이 │ 다음 스테이지(유효할 때) / 스테이지 선택
```

- **스테이지 카드 상태:** `잠김` · `선택 가능` · `클리어` · `콘텐츠 오류`(검증 실패, 진단 문구 표시, 선택 불가). 해금: Stage 1은 항상 선택 가능, Stage N은 Stage N−1 클리어 시(SPEC 10절 "플래그에서 파생"). UI-01에서 클리어 플래그는 **세션 메모리**에만 있다. 영구 저장·저장 상태(대기·성공·실패)는 SAVE-01이 같은 인터페이스(`ProgressStore`)로 연결한다.
- **진입:** `validateStageForEntry`(진입 재검증) 실패 시 시작하지 않고 카드를 `콘텐츠 오류`로 표시.
- **재도전:** 같은 스테이지로 새 `attemptId` 시도(`createAttempt`), 이전 시도 상태를 넘기지 않음. 클리어 플래그 유지.
- **결과 오버레이:** Stage 이름·도달 웨이브·남은 기지 HP, 버튼 `재도전`·`스테이지 선택`·`다음 스테이지`(Stage 3에는 없음, 다음 스테이지가 콘텐츠 오류면 비활성). 결과 단계에서는 게임플레이 입력이 코어에서 거부되며 UI도 조작을 막는다.

## 5. 세션: 시간·명령

- `advance(elapsedMs)`: 누적 후 50ms마다 `step()` 1회, **한 번에 최대 5틱**, 나머지 누적은 버린다(SIM-CONTRACT 2절). 일시정지·결과 단계·화면 숨김(`visibilitychange` hidden)에서는 누적하지 않는다. 숨김 → 보임 복귀 시 누적은 0부터 시작. **숨김(앱 백그라운드·탭 전환)으로 바뀔 때 진행 중 시도(준비·전투, 이미 일시정지·결과가 아님)는 자동 일시정지**(MOB-02, MOB-01 리뷰 F7)하며, 복귀하면 메뉴(일시정지) 화면이 보이고 사용자가 재개한다.
- 일시정지: HUD 상단 `⚙` 메뉴 버튼(메뉴를 열면 일시정지), 키보드 `Space`/`P`, Android 뒤로가기(8.1절). 코어 `pause()`/`resume()`을 쓰고, 렌더 VFX도 함께 멈춘다(SPEC 9절). 일시정지 중 게임플레이 조작 버튼은 비활성.
- 명령은 모두 세션 메서드로: `build(type, cell)`, `upgrade(towerId)`, `sell(towerId)`, `setTargeting(towerId, mode)`, `startWave()`. 세션은 접수 결과와 **다음 틱 이벤트의 `commandRejected`**를 받아 사용자 피드백으로 바꾼다. UI가 미리 막는 조건(골드 부족 버튼 비활성 등)은 **표시 편의**일 뿐이며, 최종 판정은 항상 코어다.
- 기록: 세션은 `createRecordedAttempt`로 시도를 만든다(나중에 리플레이·버그 재현용으로 `finish()` 가능). 이 기록은 UI-01에서 저장하지 않는다.

## 6. 맵 입력·선택 상태 (UI 상태, 코어 밖)

| UI 상태 | 진입 | 맵 탭 동작 | 해제 |
|---|---|---|---|
| 기본 | — | 타워 있는 칸 → 그 타워 선택. 빈 칸 → 선택 해제 | — |
| 설치 모드(종류 T) | HUD 타워 목록에서 T 탭 | 칸 → `build(T, 칸)` 제출 후 **설치 모드 종료**(성공·실패 무관, SPEC 9절 "1개 설치하고 종료") | 같은 항목 다시 탭, `Esc`, 맵 밖 탭 |
| 타워 선택(id) | 맵의 타워 탭 | 기본과 같음 | 빈 칸 탭, `Esc`, 타워 판매·사라짐 |
| 판매 확인(id) | 상세의 `판매` | 확인창 표시 중 맵 입력 무시 | `취소`, **준비→전투 전환 시 자동 취소**(SPEC 9절), 타워 사라짐 |

- 좌표 변환: Phaser 포인터 좌표(맵 영역 기준) → `pointToCell(x, y, tile)`(SIM-CONTRACT 10.1). `null`(맵 밖·레터박스)이면 설치 명령을 만들지 않는다. HUD는 DOM이므로 HUD 탭이 맵 명령을 만들 수 없다.
- 설치 모드에서 칸 위 미리보기: 설치 가능/불가 색, 그 종류 Lv1 사거리 원. 터치 기기는 미리보기 없이 탭 즉시 제출(호버 없음).
- 선택된 타워: 사거리 원 표시, HUD에 간단 패널(종류·레벨·강화·판매·`정보`), `정보` 창에 능력치·타깃 모드(7절).
- 일시정지 해제 후 남은 UI 상태(선택·설치 모드)는 유지하되 명령은 코어가 재검증(SPEC 9절).

## 7. HUD 내용 (SPEC 9절, MOB-02 개편 2026-11-26)

사용자 결정(2026-11-26): 오른쪽 HUD에는 자주 쓰는 것만 한 화면에, 나머지는 메뉴로.

- **HUD 상시 항목(스크롤 없음):**
  - 1줄: 골드, 기지 HP(`현재 / 최대`, 30% 이하 빨강).
  - 2줄: 웨이브 `N / 5`와 단계 짧은 표시(`준비`·`전투`, SPEC 9절 "현재 단계 항상 표시"), `⚙` 메뉴 버튼.
  - 준비 단계에서만: `지금 시작` 버튼에 남은 시간을 함께 표시(예: `▶ 시작 12.3초`, 소수 1자리 = 틱 × 0.05).
  - 타워 목록 4종(2열 격자): 종류 색 표식·이름·설치 가격. 골드 부족이면 흐리게(탭은 가능하되 코어 거부 피드백).
  - 선택한 타워 패널: `이름 Lv`와 `정보` 버튼 1줄, `강화 가격`·`판매 +환급` 두 버튼을 1줄에 나란히. `강화`(Lv4면 `최고`, 비활성), `판매`(준비 단계에서만 활성, 전투 중 비활성이며 누르려 하면 안내 없이 흐림 — "준비 단계에서만 판매" 문구는 정보 창에 둔다).
- **메뉴(`⚙`, 일시정지 화면 겸용):** 열면 `pause()`, 닫거나 `계속하기`를 누르면 `resume()`. 내용: 스테이지 이름, `임시 수치` 배지, 단계(`준비`·`전투`), 전투 중이면 생성 진행 `생성 k / 전체`·생존 적 수, 버튼 `계속하기`·`스테이지 선택`(현재 시도를 버리고 선택 화면으로, 확인 1회). 결과 단계에서는 메뉴를 열 수 없다(결과 오버레이가 대신함).
- **타워 정보 창(`정보`):** 일시정지하지 않는 작은 창(맵 영역 위). 능력치(피해·공격 주기·사거리·광역·둔화), 타깃 모드 4버튼 `선두`·`후미`·`가까운`·`강한`, 판매 조건 안내, `닫기`. 창이 열린 동안 맵 입력은 무시하고(판매 확인과 같음), 선택한 타워가 사라지면 닫힌다. 타깃 변경은 일시정지가 아니므로 코어에 그대로 제출된다(SIM-CONTRACT 12.2: 일시정지 중 명령은 거부되므로 메뉴에 넣지 않음).
- **피드백:** 거부 사유를 짧은 한국어 문구로 2초 표시. 사유 문구 표(`insufficientGold` → "골드가 부족합니다", `notBuildable` → "여기에는 설치할 수 없습니다", `occupied` → "이미 타워가 있습니다", `outOfGrid` → "맵 밖입니다", `maxLevel` → "최고 레벨입니다", `wrongPhase` → "지금은 할 수 없습니다", `towerNotFound` → "타워가 없습니다"). 그 밖의 사유는 "명령이 거부되었습니다(사유 코드)".
- 화면 문구는 한 파일(`src/game/ui/strings.ko.ts`)에 모은다.
- 표시 값은 모두 **코어 스냅샷에서 파생**하는 순수 함수(`hudView(snapshot, stage, uiState)`)로 만든다. HUD가 따로 값을 계산·누적하지 않는다.

## 8. 렌더 (단순 도형, 사용자 결정)

- 스테이지별 팔레트(DESIGN.md 시안 색감): Stage 1 잔디 초록·황토 길, Stage 2 눈 흰색·회청 길, Stage 3 어두운 석재·밝은 석판 길. 격자선 낮은 대비. 출발 칸·기지(성문) 칸 표식.
- 타워: 칸 안 정사각형 + 종류 색(궁수 금색·발리스타 적색·마법 보라·서리 하늘색) + 레벨 표시(점 1~4). 적: 원 + 유형 색, 크기 차이(군집형 작게·중장형 크게), HP 바, 특성 표식(작은 모서리 기호 3종). 투사체: 작은 점(마법은 원형 폭발 짧은 링, 서리 명중은 청백 링).
- 위치는 코어 상태(`progressToPosition`, 투사체 `pos`)를 그대로 그린다. **틱 사이 보간**은 허용하되 시각 전용이며(직전·현재 스냅샷 선형 보간) 게임 상태에 영향 없음. 취소·만료 투사체의 잔상·폭발 링 같은 VFX는 이벤트로 그리고 짧은 시간 뒤 사라진다. 일시정지 시 VFX도 정지.
- 실제 스프라이트 교체를 위해 그리기를 종류별 함수로 분리(`drawTower(type, level)` 등).

## 8.1 Android 뒤로가기 (MOB-02)

- 우선순위(보이는 최상위부터): 판매 확인 → 취소 · 메뉴 안 스테이지 선택 확인창 → 닫기 · 메뉴 열림 → 닫고 재개 · 타워 정보 창 → 닫기 · 전투 화면(준비·전투) → 메뉴 열기(일시정지) · 결과 오버레이 → 스테이지 선택 · 스테이지 선택 화면 → 앱 종료(기본 동작).

## 10. 진행 저장 (SAVE-01, 2026-11-26)

기준: SPEC 10절(로컬 클리어 플래그, 해금 파생, 저장 실패·재시도·손실 안내, 기존 클리어 유지), PLAN 5절.

- **저장 대상:** 클리어한 `stageId` 목록만. 해금·카드 상태는 저장하지 않고 `deriveStageCards`로 파생(기존 그대로).
- **저장소:** WebView/브라우저 `localStorage`, 키 `ddooby-defence.progress`. 값 `{"version":1,"cleared":["stage-1",...]}`(정렬·중복 없음). Android 앱은 앱 전용 WebView 저장소에 남아 앱을 껐다 켜도 유지된다(앱 삭제·데이터 삭제 시 사라짐).
- **인터페이스:** `ProgressStore`를 저장 상태를 알 수 있게 넓힌다. `load()` 결과(`ok`·`empty`·`unreadable`·`unavailable`), `markCleared(stageId)` 결과 저장 상태 `saved`·`failed`, `retrySave()`. 저장 백엔드는 주입 가능한 `{getItem,setItem,removeItem}`(테스트에서 실패·예외·용량 초과 흉내). localStorage는 동기라 `대기` 상태는 화면에 거의 안 보이지만 상태 값은 둔다(SPEC 9절 "대기·성공·실패").
- **세션 우선:** 클리어는 저장 성공 여부와 무관하게 **현재 실행 중 메모리에 즉시 반영**(해금 유지). 저장 실패면 결과 오버레이에 `기록 저장 실패` + `다시 저장` 버튼 + "앱을 다시 켜면 이 클리어 기록이 사라질 수 있습니다" 안내. 성공이면 작게 `기록 저장됨`.
- **유지:** 이미 클리어한 스테이지를 다시 하다 패배해도 플래그 유지. 재도전·스테이지 전환은 저장 기록을 건드리지 않는다. 플래그를 지우는 경로는 없다(초기화 기능은 MVP 밖).
- **읽기 실패:** JSON 깨짐·형식 불일치·모르는 `version`이면 기록을 **덮어쓰지 않고** 원문을 `ddooby-defence.progress.corrupt`에 한 번 옮겨 둔 뒤 빈 기록으로 시작, 스테이지 선택 화면에 "저장 기록을 읽지 못해 새로 시작합니다" 안내. 저장소 자체를 못 쓰면(`unavailable`, 예외) 메모리로만 진행하고 "기록이 저장되지 않습니다" 안내.
- **쓰기 전 재확인(리뷰 SAVE-01 F1·F2):** 본 키에 쓰기 전에 **매번 본 키를 다시 읽는다.** 정상 기록이면 메모리 목록과 **합집합**으로 써서 읽지 못했던 기존 클리어를 잃지 않는다. 다시 읽기가 예외면 쓰지 않고 `failed`. 본 키가 읽을 수 없는 원문이면 그 원문이 백업 키 중 하나에 **똑같이 보존된 것을 확인한 뒤에만** 덮어쓴다. 보존 확인·백업 쓰기가 실패하면 쓰지 않고 `failed`(메모리 해금은 유지, `다시 저장`으로 재시도).
- **백업 키:** `ddooby-defence.progress.corrupt`, 이미 다른 원문이 있으면 `ddooby-defence.progress.corrupt.2` … `.corrupt.5` 중 빈 칸. 같은 원문이 이미 있으면 그것으로 보존 확인. 5칸이 모두 다른 원문이면 덮어쓰지 않고 `failed`(사실상 발생하지 않는 경계, 안내 문구는 일반 저장 실패와 같음).
- **모르는 stageId:** 현재 콘텐츠에 없는 id는 해금 파생에 쓰지 않지만 저장 값에서는 지우지 않고 보존(콘텐츠가 바뀌어도 기록 손실 방지). 문자열이 아닌 항목만 버린다.
- **Android 백업:** `allowBackup="true"`(현재 기본값) 유지 — 폰 교체·재설치 시 Google 자동 백업으로 기록이 옮겨질 수 있다. (claude-main 제안, 사용자 확인 대기)
