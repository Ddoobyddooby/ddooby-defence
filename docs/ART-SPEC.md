# ART-SPEC — ART-03 게임 스프라이트 규격 (v0.1)

> 상태: 규격 초안(claude-main). 시안 → **사용자 선택** → 전체 제작 → 구현 순서. 시각 방향은 ART-01 선택 시안(`docs/DESIGN.md`)을 따른다.

## 1. 사용자 결정 (2026-11-26)

| 항목 | 결정 |
|---|---|
| 맵 | **타일 + 장식**: 바닥·길 타일을 코드가 경로 데이터대로 깐다(칸과 길이 항상 정확히 일치, 맵을 바꿔도 그림 재작업 없음) |
| 타워 레벨 | **레벨마다 그림**: 4종 × Lv1~4 = 16장, 같은 석조 몸체에 상단 장치·장식이 단계별로 화려해짐 |
| 움직임 | **한 장 + 코드 움직임**: 프레임 애니메이션 없음. 적은 걷는 듯 흔들림·좌우 뒤집기, 타워는 발사 반동, 발사체·폭발은 코드로 이동·확대·투명화 |

## 2. 공통 규격

- 형식: PNG, sRGB, **투명 배경**(바닥 타일만 불투명). 정사각형, 크기는 아래 표. 실제 표시 크기는 칸 28~93 CSS px(UI-CONTRACT 3절) × 기기 배율 → 128px 원본이면 충분.
- 시점: ART-01과 같은 **정면에 가까운 내려다보기(약 3/4)**, 빛은 왼쪽 위. 모든 스프라이트 같은 시점·같은 빛.
- 화풍: ART-01 시안의 손그림 판타지(굵은 외곽선, 묶음 명암, 절제된 색, 48px에서도 실루엣 식별).
- 글자·로고·숫자 넣지 않음. 그림자는 스프라이트 안에 아주 옅게(바닥 접지용)만.
- 파일명은 아래 표 그대로(소문자, 하이픈).

## 3. 목록

### 3.1 맵 타일 (테마마다, 128×128)

> 파일 번호 `s1`·`s2`·`s3` = **테마** 초원·설원·폐허. 스테이지 → 테마: Stage 1→s1, 2→s2, 3→s3, **4→s2(설원), 5→s3(폐허)**(STAGE-45, 사용자 결정 2026-11-27). Stage 4·5용 새 그림은 없다. 생성 지점은 맵 가장자리 어느 쪽이든(Stage 4는 위쪽) 올 수 있고, 기지는 맵 안쪽(Stage 5 가운데)일 수 있다.

테마: Stage 1 초원(잔디·황토 흙길), Stage 2 설원(눈밭·회청색 길), Stage 3 폐허(어두운 석재·밝은 석판 길).

| 파일 | 내용 | 조건 |
|---|---|---|
| `s{1,2,3}-ground-{1,2,3}.png` | 설치 가능한 바닥 3변형 | **상하좌우 이음매 없이 반복**, 3변형이 섞여도 경계가 안 보임. 큰 물체 금지(모든 비경로 칸은 설치 가능하므로 막힌 것처럼 보이면 안 됨). 작은 풀·돌·눈 결 정도만 |
| `s{1,2,3}-path-straight.png` | 길 직선(왼쪽→오른쪽) | 길 폭은 칸의 약 80%, 길 가장자리는 바닥과 자연스럽게. 좌우 끝이 이어 붙음. 코드가 90° 회전해 세로로도 씀 |
| `s{1,2,3}-path-corner.png` | 길 모퉁이(왼쪽에서 들어와 아래로 나감) | 코드가 회전해 4방향 모퉁이로 씀. 직선 타일과 이음매 일치 |
| `s{1,2,3}-spawn.png` | 생성 지점(맵 왼쪽 끝 첫 칸) | 투명. 동굴 입구·나무 문 등, 칸 안에 맞춤. 길 타일 위에 겹침 |
| `s{1,2,3}-gate.png` | 기지 성문(경로 마지막 칸) | 투명. ART-01 청록 깃발 석조 성문. 칸보다 최대 1.5배까지 위로 커도 됨(아래 기준점 = 칸 아래쪽) |

### 3.2 타워 (128×128, 투명) — 16장

`tower-{archer,ballista,mage,frost}-{1,2,3,4}.png`

- 공통 회색 석조 몸체(성가퀴), 종류는 상단 장치와 전면 깃발 문양·색(DESIGN 타워 표). 몸체 바닥 중심이 그림 가로 중앙·아래쪽 약 85% 지점.
- Lv1 → Lv4: 장치가 커지고 금속·보석 장식, 깃발 테두리(Lv2 은, Lv3 금, Lv4 금+빛)처럼 **한눈에 단계 구분**. 실루엣 크기는 Lv4도 128 안(위로 약간 더 높아지는 정도).
- HUD 타워 버튼 아이콘은 Lv1 그림을 축소해 쓴다(별도 파일 없음).

### 3.3 적 (128×128, 투명) — 4장

`enemy-{normal,fast,heavy,swarm}.png` — 일반 해골(둥근 방패), 고속 늑대, 중장 오크(철제 견갑·엄니), 군집 고블린(작은 단검, **한 마리**). **오른쪽을 향함**(왼쪽 이동 시 코드가 뒤집음). 발 위치 = 그림 가로 중앙·아래쪽 약 85%. 크기감: 오크 > 해골 ≈ 늑대 > 고블린(고블린은 그림 안에서 작게).

### 3.4 특성 표식 (64×64, 투명) — 3장

`trait-{resist,hp,speed}.png` — 제어 저항(사슬 끊긴 방패 등), 체력 강화(붉은 하트+), 속도 강화(날개·겹화살표). 체력 바 옆 작은 크기(약 14~20px)에서 구분되게 단순·굵게, 색 서로 다르게.

## 4. 제작 순서

1. **시안(1차)**: Stage 1 타일 전부 + 타워 4종 Lv1 + 궁수 Lv1~4 + 적 4종 + 특성 3 + 발사체·효과 일부, 그리고 이 조각들로 실제 18×10 Stage 1 경로(SIM-CONTRACT 10절 waypoint)를 짜 맞춘 **합성 미리보기 1장**(HUD 제외, 1800×1000). 화풍 2안 이내. → 사용자 선택.
2. **전체 제작**: 선택 화풍으로 3절 전부. 합성 미리보기 3스테이지.
3. **구현**(claude-1/2): `public/assets/game/`에 복사, Phaser 로드·렌더 교체(단순 도형은 로드 실패 시 대체로 유지), 코드 움직임, 실기기 확인.

## 6. 구현 메모 (ART-03 코드 기반, claude-1)

- 그림 위치 `public/assets/game/<이름>.png`(이름은 3절 표, 코드 상수 `src/game/phaser/assets.ts` `ASSET_NAMES` 52개). 공통 그림(타워·적·특성·발사체·효과)은 시작 때, 스테이지 타일 7장은 그 스테이지를 처음 열 때 불러온다. 없거나 실패한 그림은 **그 요소만** 이전 단순 도형으로 그려지고 다시 요청하지 않는다(404 는 파일마다 한 번씩 브라우저 네트워크 로그에 남을 수 있다).
- 길 타일: `pathTiles.ts` 가 경로 칸마다 straight|corner + 회전(시계 방향), 첫 칸 spawn·끝 칸 gate(아래에 길 타일도 함께)를 계산. 바닥 변형은 `groundVariant(col,row)`.
- 성문(gate)은 칸 아래쪽을 기준점으로 가로·세로 1.5칸 크기로 그린다(규격 "최대 1.5배" 해석).
- 적·타워 기준점은 그림 아래 85%(적은 칸 중심보다 약간 아래에 발), 적은 오른쪽 원본·왼쪽 이동 시 좌우 뒤집기·걷는 흔들림, 타워는 발사 반동(시각 전용, 일시정지 동결).
- DPR: 캔버스 내부 해상도 = CSS × `min(3, devicePixelRatio)`, CSS 크기 유지, 장면 좌표는 CSS px(카메라 zoom 으로 배율). 입력은 이벤트 시점 캔버스 CSS 사각형 기준이라 배율과 무관(`dpr.ts`).
